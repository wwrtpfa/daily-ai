claude-code

今日有发布打开仓库

终端中的编码 Agent，支持读代码、执行工具和协作开发。

解决什么

官方 README 把它定义为「住在终端里的编码工具」：理解你的代码库，用自然语言交代任务后执行常规改动、解释复杂代码并处理 Git 工作流，也能在 IDE 或 GitHub 上 @claude 使用。它改变的不是某一个编辑器功能，而是「读代码—改文件—跑命令—提交」这几步之间反复切换的往返。

谁在用

  • 在既有仓库里实现需求、需要 Agent 读懂整个代码库的开发者。
  • 要让 Agent 在权限约束下执行任务的团队（配合沙箱与文件写入规则）。
  • 在 GitHub issue / PR 里 @claude 做协作的团队。

什么时候别用 / 边界

需要完全离线运行，或要求仓库本身提供完整可自由再发行的客户端源码。

专有条款，GitHub API 未识别 SPDX，不要按宽松开源许可假设再发行。README 说明会收集代码采纳/拒绝、相关会话数据与 /bug 反馈；生产使用前需核对官方数据策略。安装命令、权限行为与今日 v2.1.321 的修复效果本站均未实测。

怎么开始

官方 Get started：安装后进入项目目录运行 claude。README 同时给出 macOS / Linux、Homebrew、Windows 与 WinGet 四种方式。

安装 · macOS / Linux（官方推荐）
curl -fsSL https://claude.ai/install.sh | bash
安装 · Homebrew
brew install --cask claude-code
安装 · Windows（官方推荐）

开始使用

README 明确 npm 安装方式已弃用（npm install -g @anthropic-ai/claude-code），并标注 Node.js 18+ 要求；安装与卸载细节见官方 setup 文档。

llama.cpp

今日有发布打开仓库

用 C/C++ 在多种硬件上运行大语言模型的推理项目。

解决什么

README 的目标是「以最少配置、在从本地到云端的广泛硬件上运行 LLM / VLM 推理」。实现是无外部依赖的纯 C/C++，支持 1.5–8 bit 整数量化降低内存占用，并提供 CUDA / Metal / Vulkan / SYCL 等后端与 CPU+GPU 混合推理——模型大于显存时也能部分加速。

谁在用

  • 在本机加载 GGUF 模型、不想先搭一套服务集群的个人开发者。
  • 需要针对 Apple Silicon / NVIDIA / AMD / Intel / 专用 NPU 选择后端的部署团队。
  • 要用 OpenAI 兼容 API 把本地模型接进应用的人（llama serve）。

什么时候别用 / 边界

期望不做模型格式、内存与硬件兼容性评估就直接上线。

后端清单来自 README 的 Supported backends 表，其中 OpenVINO 标为 [In Progress]，不等于稳定可用。量化、混合推理与性能描述均为项目自述，本站未编译、未跑任何后端或基准。今日 b12244 更新的是 Intel 相关构建依赖，不能推导吞吐或延迟提升。

怎么开始

官方 Quick start 提供脚本安装、Docker、预编译二进制与源码构建四种方式；安装后可直接从 Hugging Face 拉模型运行。

脚本安装 · macOS / Linux
curl -LsSf https://llama.app/install.sh | sh
命令行直接跑一个模型
llama cli -hf ggml-org/Qwen3.5-0.8B-GGUF
启动 OpenAI 兼容 API 服务
llama serve -hf ggml-org/Qwen3.5-0.8B-GGUF

Windows 可用 irm https://llama.app/install.ps1 | iex；Docker 与源码构建分别见 docs/docker.md、docs/build.md。

agent-framework

补录 · 今日无发布打开仓库

微软的 Agent 应用框架，提供 Python 与 .NET 开发入口。

解决什么

微软把它定位为「面向生产级 AI Agent 与多 Agent 工作流的多语言框架」，Python 与 .NET 为主，Go SDK 另有独立仓库。它解决的是从原型走到生产之间的编排问题：图结构工作流支持顺序、并发、交接与群组协作，并带 checkpointing、OpenTelemetry 可观测性、human-in-the-loop 与中间件。

谁在用

  • 要把 Agent 从原型搬到生产、需要耐久性与可重启的团队。
  • 需要多 Agent 编排（顺序 / 并发 / 交接 / 群组）而非单次提示循环的开发者。
  • Python 或 .NET 技术栈，且接受 Azure / Foundry 相关依赖的团队。
  • 从 Semantic Kernel 或 AutoGen 迁移、需要官方迁移指南的团队。

什么时候别用 / 边界

只想使用现成聊天产品，不打算开发应用与维护依赖。

Quickstart 不是零配置本地示例，依赖 Microsoft Foundry 与 Azure 凭据。README 明确：接入第三方模型/服务器时的数据流、成本与合规边界由使用者负责，生产用需自行实施 responsible AI 缓解措施。仓库主语言字段为 Python，但框架同时提供 .NET 与独立 Go SDK。本站未运行示例、未评估稳定性。

怎么开始

官方 Quickstart 的最小示例依赖 Microsoft Foundry 与 Azure 凭据，先用 az login 准备凭据。

安装 · Python
pip install agent-framework
安装 · .NET
dotnet add package Microsoft.Agents.AI
准备 Azure 凭据
az login
最小示例 · Python（摘自官方 Quickstart）
from agent_framework import Agent
from agent_framework.foundry import FoundryChatClient
from azure.identity import AzureCliCredential

agent = Agent(client=FoundryChatClient(credential=AzureCliCredential()),
              name="HaikuAgent",
              instructions="You are an upbeat assistant that writes beautifully.")
print(await agent.run("Write a haiku about Microsoft Agent Framework."))

示例需在 async 函数中使用 asyncio.run(main()) 调用；实验模块 agent-framework-lab 需单独安装。.NET 示例另需 Microsoft.Agents.AI.Foundry、Azure.AI.Projects 等包。
