### 诊断结论（供后续沿用）

1. **首屏回答的是编辑的问题**：品牌/期号 → 抽象主线「模型向前，边界也要跟上」→ 流程插画 +「阅读本期」→ 第 1 条通稿式标题。读者第一眼问的是「跟我有关吗 / 今天要不要动手 / 没事我能走吗」，一个都没回答。
2. **答案已在数据里却被折叠**：`content/days/2026-11-10.json` 的 `scenes` 其实就是「谁该做什么」（例：使用 MCP OAuth 的团队检查版本并测试登录流程），`caveat` 是「别信什么」，两者都藏在 `<details>「事实与边界 +」` 后面；首屏的 `verdict` 是通稿复述、`why` 是编辑视角观察。
3. **承诺 > 交付**：导航 4 页 + 周报/往期/状态/分享图，但真实内容只有 1 期（4 条动态、3 个项目），周趋势与历史对比是空壳。首屏越像完整刊物，落差越大。
4. **缺少「变化」维度**：日报的复利是「和上次比什么变了」，当前产品没有设计这个能力。

### 提出的三个方向（待用户选，未实施）

- A（推荐）**「今天要不要动手」决策式日报**：首屏直接给「谁 → 该做什么」+「谁不用管」，来源/边界可展开；砍掉大主线、抽象插画、周报/状态首屏入口。用现有 schema 就能做，改动最小。
- B **「别被误导」可信度日报**：把 caveat 做成主角，主打厂商自选数据/未复跑/规划≠产出；差异化最锋利但受众窄、内容生产成本高。
- C **「只盯你正在用的东西」依赖追踪**：追踪自选模型/仓库的版本、许可、破坏性改动、弃用；需重做采集与内容模型，工程量最大。

### 踩到的坑

1. 本机路径代理不识别单独的 `mkdir(exist_ok=True)`，目录已存在会抛 `FileExistsError`；统一写 `parents=True, exist_ok=True`。
2. 闭合 `<details>` 的子元素仍参与 Chromium 的 min-content 计算，导致 390px 下 `scrollWidth=677`；用 `details:not([open])>.evidence-body,.table-scroll{display:none}` + flex 项 `min-width:0` 修复。
3. `agent-browser click` 对首屏外元素会点到空坐标（返回 Done 但无效果），必须先 `scrollintoview`；排查时用 `document.elementFromPoint` 确认。
4. 深色主题下不能把浅色 token 写进 SVG `fill` 属性；改 CSS 变量后暗色实测正常。
