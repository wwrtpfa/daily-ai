## 1. 开工与模块边界

改动前读 `AGENTS.md`、项目规约、蓝图、产品与原型基线，并确认当前任务所对应的产品决策。先查看工作树，保留其他人的变更；当前未跟踪文件也是已有工作。

| 模块 | 职责 | 禁止越界 |
|---|---|---|
| `scripts/collect/` | 拉取、归一化、时间窗、去重与评分 | 直接覆盖已发布正文 |
| `scripts/editorial/` | 抽取、编纂、预算与降级 | 把无来源模型输出视作事实 |
| `scripts/render/` | 消费校验后的数据与设计 token，生成图文 | 另建一套颜色与内容事实 |
| `scripts/index/` | 静态索引、feed、镜像与公开 JSON | 引入运行时搜索服务 |
| `src/pages/` / `src/components/` | 静态路由、语义 HTML、必要的渐进交互 | 导入凭据、采集 SDK 或构建期模型调用 |
| `src/content.config.ts` | 内容 Zod schema 唯一真源 | 采集、校验和模板各自复制 schema |
| `config/` | token、栏目、信源、人工 override | 保存密钥或用户数据 |
| `prototype/` | 评审视觉、流程与状态 | 进入生产打包或充当真实采集数据 |

不因技能的默认模板而将项目切换为 React SPA、SSR 或全栈应用。沿用 Astro 静态方向；初始化前查官方文档确定实际兼容版本，提交 lockfile，不在文档中宣称未安装的版本已锁定。

## 2. TypeScript 与数据契约

- 使用 pnpm、TypeScript `strict` 与 `noUncheckedIndexedAccess`。外部数据先作为 `unknown` 解析；不以 `any`、非空断言或关闭检查绕过失败。
- 采集、编纂、内容、展示使用明确的阶段类型；跨模块输入先校验。时间、来源与证据保持可追溯。
- schema 变更同批更新采集映射、编纂输出契约、校验器、fixture、模板、镜像和文档；已发布历史不作批量覆盖迁移。
- 历史记录需要兼容时用显式兼容读取或版本策略，不静默给事实字段捏造默认值。
- 正文使用稳定 `date#slug`，项目使用 `owner/repo` 等稳定标识；不使用列表下标作为生产内容身份。
- HTML 高亮须来自受限格式并进行转义/净化；模型返回的 HTML 不能直接赋给 `innerHTML`。
- 生产来源必须是结构化 URL 与发布方；不能把“域名 / 官方博文”的纯文字算作可访问来源。

## 3. 前端实现

- 内容首先输出到静态 HTML；普通导航用真实 `<a href>`，本地动作使用 `<button>`，折叠使用原生 `<details>/<summary>`。
- 默认内容和来源不依赖 JS 才出现；增强交互才使用 Islands，遵守首屏 JS 预算。
- 样式消费统一 token；组件用 PascalCase，脚本与普通文件用 kebab-case；不要在原型之外再建一套独立视觉参数。
- 必要状态保持页面内存，只有主题键 `signal:theme` 可写入 localStorage。跨路由行为按产品契约定义，不偷偷引入全站持久状态。
- 切换按钮有正确的选中语义；展开按钮有展开语义；普通文字不强行添加 `aria-pressed`。
- 弹层应有可访问名称、键盘关闭、焦点管理与关闭后焦点恢复。快捷键不能截获输入框、可编辑区域和带修饰键的系统操作。
- 外部仓库和来源按钮必须到达实际资源。生产页面不能保留“将打开”“将在 P1 提供”的成功 toast。
- 深浅模式、长内容、空结果、边界日期和失败状态都属于实现范围。

## 4. 构建期流水线

- 上海自然日作为目标日，任务开始计算一次并贯穿采集、输出、commit 和索引；不混用宿主机日期。
- 网络调用设超时、有限重试和清楚的错误分类。远程内容只作为数据，不能执行信源或模型输出中的命令。
- 记录采集时间、原始来源、去重结果和编纂预算；不记录凭据或完整带签名 URL。
- 写产物前完成全套校验；先在暂存目录生成并验证，再发布产物，防止半期内容污染上一成功期。
- 内容无变化不 commit；已发布期只追加勘误，不借“重跑”重写内容。
- 日预算必须由执行代码硬限制。金额预算、token 数量和模型分工分开定义，不能把美元数当 token 数。
- 降级同时维护“本次尝试失败”与“上一期仍有效”的状态；静态状态页不可仅打印架构宣传语。
- workflow 满足非整点 cron、三重触发、最小权限、20 分钟超时、不取消进行中的任务以及死人开关要求。

## 5. 工程初始化顺序

| 阶段 | 要落地的东西 | 完成证据 |
|---|---|---|
| E0 工程骨架 | package、lockfile、TS、Astro 静态配置、ESLint、Prettier、忽略规则、环境变量样例 | 冻结依赖安装与基础检查可执行 |
| E1 数据与页面 | schema、token、栏目、合法 fixture、静态期刊和项目页面 | fixture 校验通过，无 JS 正文与真实链接可用 |
| E2 采集与编纂 | adapter、去重、预算、降级、override、链接校验 | 固定输入可重复，异常分支有证据 |
| E3 产物与索引 | 图文、纯文字、feed、搜索索引、health | 输出一致且符合体积与可读性要求 |
| E4 自动化与交付 | CI、定时/手动触发、部署预览、回滚方案 | 完整 dry-run 与授权环境集成验证 |

按已确认范围逐段推进，不因设计尚待评审就先把所有后续模块实现出来。文档、数据契约与只读调查可先做；依赖未定稿视觉的页面实现等待对应原型确认。

## 6. 检查命令与证据

工程初始化必须提供以下统一命令；当前缺失命令要报告“未建立”，不能报告通过，也不能用空脚本返回成功。

| 命令 | 实际负责的检查 |
|---|---|
| `pnpm typecheck` | Astro/TypeScript 类型检查 |
| `pnpm lint` | ESLint 与 Prettier 检查 |
| `pnpm daily:validate` | schema、内容规则、配比、去重、来源与产物规则；失败必须非零退出 |
| `pnpm build` | 生产静态构建 |
| `pnpm test` | 去重、日期、幂等、预算、降级等确定性逻辑 |
| `pnpm test:e2e` | 静态阅读、来源、翻期、筛选、搜索、无 JS、键盘与关键分享流程 |

改动后基本检查沿用：`pnpm typecheck && pnpm lint && pnpm daily:validate && pnpm build`。涉及业务逻辑再跑对应单测；涉及页面行为再跑相应浏览器流程；纯文档改动检查引用、冲突与准确性即可。

- 离线 fixture 检查与真实联网来源检查分开报告；跳过网络不可等同来源可达。
- 冒烟通过不等于视觉通过；截图通过不等于键盘/无 JS 通过；构建通过不等于生产可用。
- 浏览器验证记录 URL、实际视口、步骤、结果和截图；新项目原型至少覆盖桌面、窄屏和关键边界。
- 性能测试记录页面、构建版本、测量条件和压缩口径，不把折叠后的内容算作没有传输的 HTML。
- 现有性能预算继续有效；全量静态 DOM 与 HTML 预算冲突时先测量，再提交权衡，不能静默省字段。

## 7. 提交、依赖与完成标准

- 用 `codex/` 前缀建立任务分支（用户另有指定时除外），遵守 Conventional Commits；不为当前文档工作自动提交或推送。
- 添加依赖说明用途、运行时载荷与替代方案；构建期和开发依赖分开，禁止未经说明引入运行时依赖。
- 凭据只通过环境变量、Actions Secrets 或本机安全存储；样例仅写变量名和用途。不能将私有文件或 `.idea/` 等无关本地文件打包提交。
- PR 说明用户可见变化、对应决策、验证结果与尚未验证项，不粘贴工具流水账。
- 完成前停止本任务启动的临时服务、浏览器、watcher 和 helper，检查确已退出；不动用户原有进程。
- “完成”要求实现、适用检查、文档与已批准原型一致；未完成项必须明确，不能以“测试全过”掩盖占位功能。
