## v0.3 候选方案记录（未获产品与视觉定稿；呈现层级规则见项目规约）

旧方案基于“功能与信息都满意”而只调整呈现。该假设已被最新反馈修正；以下保留候选方案的来由，不再作为禁止产品取舍的依据。

**诊断：AI 味的根源不是风格，是权重。** v0.2 首屏同时摆了报头、副标、7 期刊期轴、导航 + 3 个工具按钮、左栏 4 个区块（索引 / 期号 / 阅读设置 / 关于）、主线标签、大标题、导语、30 秒速览框、条目 —— 12 个模块被同等认真地渲染。人做的界面会替读者取舍；生成式界面倾向于「每个字段都值得展示」，因为它不承担「少展示一条」的责任。更关键的是：v0.2 换上的米色纸 + 衬线 + 朱红 + 发丝线那套「反 AI 味皮肤」，本身已经是生成站最泛滥的模板 —— **用模板反模板，只会更像模板**。

| # | v0.3 处理 |
|---|---|
| 1 首屏唯一主角 | 首屏只留：一行导航、日期/期号、54px 今日主线、导语、一行「上一期」入口。工具行减到 3 项文字按钮，其余全部下移或折叠 |
| 2 信息分层而非删除 | 7 期刊期轴移到页脚；左栏索引并入可折叠速览；期号 / 设置 / 关于并入页脚；解释型长文收进 `<details>`。原先有“39 项通过”的历史声明，但仓库无对应脚本与结果，当前未复验 |
| 3 条目字段分两层 | 默认：编号 / 标题 / 结论 / 为何关注（**无标签，靠段落关系**）。展开：事件 / 关键事实 / 适用场景 / 边界 / 来源 / 四类信号。`facts / scenes` 仍在 DOM 且一键可达 |
| 4 项目字段分两层 | 默认：项目名 / 一句话定位 / 解决什么问题 / 语言许可与增量。展开：适用场景 / 什么时候别用 / 为何值得看 / 完整事实 / 走势 / 主题 / 同类 |
| 5 删掉「解释界面的话」 | 「30 秒速览 · 不用点开就能读完」「用来判断这一波热度集中在哪一层」「点日期直接读那一期」「为什么这里不叫最受欢迎」等自我解说全部删除或收进折叠。**在界面里解释自己的设计，是浓度最高的 AI 味** |
| 6 视觉回到纯文本 | 白底黑字 + 两阶灰 + 一处朱红；无卡片、无边框块、无底色区、无分割线阵列；靠 52px 留白与序号分组；字号只留 54 / 21 / 16 / 13.5 四档。图表仍在，但只在内页且去掉说明文字 |

**去 AI 味的四条可验收判据**（替换 v0.2 的风格清单）：
1. **一屏一个焦点**：首屏最大字号与次大字号之比 ≥ 2.5，且只有一个元素处在这个量级。
2. **界面不解释界面**：UI 文案里不出现「用来…」「为什么这里…」「不用点开就能…」「本模块…」这类元叙述；要讲道理放到页脚折叠或文档里。
3. **同屏视觉组 ≤ 6**：把首屏按留白切成组，超过 6 组即判不合格（v0.2 为 12）。
4. **去色、关动效、去掉装饰后仍是同一份内容**：信息不依赖颜色、边框、卡片、图标才能被理解。

> **与长期内容偏好的取舍**：内容偏好要求「关键词多色高亮 + 配图给够」。v0.3 在 UI 上降级为「标题里一个朱红关键词 + 正文极淡双色底 + 内页信息图」，因为同屏出现四色高亮与多张图表会直接破坏单一焦点。**生成图文（OG / 分享卡 / 长图）与文章正文仍按原偏好保留多色与配图**，两者不冲突：UI 是阅读界面，图文是传播物料。

## 改版决议 v0.2（历史留档；与 v0.3 冲突处以 v0.3 为准）

v0.1 的原型被判定为「功能清单式 UI」：把要做的模块都摆出来，却没有解决**用户怎样在最短时间里读懂一件事**。v0.2 按刊物重做，六条硬改动：

| # | v0.1 的问题 | v0.2 的处理 |
|---|---|---|
| 1 | GitHub 页只有项目名 + star 增量，用户「先了解」的需求落空 | **Trending 页升级为「项目档案」**：每个项目必填 一句话定位 / 解决什么问题 / 适用场景 / 什么时候别用 / 为什么今天（本周）值得看 / 主题 / 事实栏（增量、累计、首次上榜、连续在榜、语言许可、7 日走势、同类可选）。**数字放在最右下角，是佐证不是主角** |
| 2 | 关键信息藏在「展开」里，读者必须点一下才知道值不值得读 | **结论前置**：标题下直接给「结论 / 为何关注 / 关键事实 / 适用场景」四行，展开只放事件全文、边界与存疑、完整来源。另加**「30 秒速览」**（全部条目的结论一屏列完）与**「只看结论」模式**（`b`）。指标从「展开率」改为「读完率」 |
| 3 | 「今日」是孤岛，昨日的信号找不到 | 顶部**刊期轴**常驻 7 期（日期 + 该期主线），点击直达；`←/→` 翻期；「往期」页默认摊开昨日全文摘要；新增**「本周」**视图（三主题 + 七期主线 + 主题演变图 + 项目短名单） |
| 4 | 视觉「AI 味」过重：圆角卡片、彩色标签云、阴影、吉祥物插画、雷达图、假仪表盘 | 改为**编辑部 / 索引卡**语言：直角、发丝线、单一强调色（朱红）、衬线标题、真实分栏与基线对齐、无阴影无渐变无 emoji。**「配图给够」改由信息图承担**（主题分布条、7 日走势、主题演变面积图、30 期密度条），而不是吉祥物插画；多色高亮降级为正文内的**下划线式 mark**，不进 UI 装饰 |
| 5 | 字号小、浅灰字段看不清 | 正文 16px / 行高 1.8，**meta 最小 12.5px 且对比度 ≥ 4.5:1**，禁止 10–11px 与低透明度文字；关键字段用字重与留白区分，不靠变浅 |
| 6 | 「我的」模块名不副实：只有今日数据，且让人误以为有服务端账户 | **删除「我的」顶级模块**。信号标记降为**本次浏览内存态**（不落 localStorage、不跨天、不上传），唯一用途是决定「今日卡片」上带哪几条；卡片为一次性客户端 Canvas 产物。**兴趣指纹、雷达、集章、本地重排、导出导入整体移出 P0–P2**，降级为 P3 可选的「本地档案」（需显式开启并告知清缓存即失） |

**关于「访问量一多会不会把前端打爆」**：不会。用户拿到的是 CDN 静态文件，浏览器不向本站发任何写入请求；标记、展开、出图都在浏览器内存 / Canvas 完成。10 UV 与 100,000 UV 对本站的区别只是 CDN 带宽，不是并发、连接数或数据库。**唯一会写的是 GitHub Actions 每天一次 `git commit`**，与访问量无关。真正要盯的是 Vercel Hobby 的 100GB/月带宽与 100 次部署/天。反过来说：**只要引入任何一个写接口（云同步 / 计数 / 账号），上面结论立刻失效**——「无账号」不是洁癖，是架构地基。这条解释已写进原型状态页，作为对外的技术主张。

**「高级感」的可验收定义**（不再停留在形容词）：
1. **颜色预算**：1 个强调色 + 4 个中性色阶；多色只出现在正文关键词的下划线上。
2. **信息密度 > 装饰密度**：首屏不交互就能读到本期全部结论。
3. **层级靠字号 / 字重 / 字距**，不靠颜色深浅；禁止用「变灰」表示次要信息。
4. **对齐到近乎固执**：所有元素落在同一套栏宽与基线；同类元素永远同一种处理。
5. **内容即视觉**：图形必须承载数据（分布、走势、演变），不承载气氛。
6. **反 AI 生成 UI 指纹清单**：渐变背景、玻璃拟态、大圆角、彩色 pill 云、emoji 图标、发光、假仪表盘、雷达图、骨架屏、卡片瀑布淡入、无来由的统计数字 —— 一律不用。
7. **细节**：中文标点避头尾、中西文间隙、`tabular-nums`、`text-wrap: balance`、高对比、`prefers-reduced-motion`。

> 判定标准：把页面截图去色后仍然读得顺、把动效全关后仍然好用、把首屏 JS 去掉后正文仍然完整 —— 三条都过，才叫高级。

## 0. 一句话定义与边界

**是什么**：一份每天 7 点前上线、5 分钟能读完、值得收藏与转发的 AI / GitHub 日报。内容静态预渲染，源码即内容库，站点即 CDN 上的一堆 HTML。

**不是什么**：不是 RSS 阅读器、不是信息流、不是社区、不是 SaaS、不做账号体系。

**三条硬约束（以及它们真正的代价）**

| 约束 | 带来的好处 | 真正要付的代价 | 应对 |
|---|---|---|---|
| 纯前端（运行时零服务） | 零运维故障面、零数据库、近零成本、隐私友好、Lighthouse 天然接近满分、**访问量与并发无关** | 无法跨设备同步、无法有全局计数、不能建用户画像 | 把「不建档」变成卖点：读完即走、无追踪、无持久化数据；云同步列为 P3 唯一破例点 |
| 源码在 GitHub | Git 即 CMS、天然版本史/回滚/协作、每日 commit 保活 cron | 内容生产链路必须脚本化；仓库会随图片增长 | 图片走 WebP/AVIF + 尺寸预算；必要时 Git LFS 或对象存储 |
| 部署在 Vercel | push 即部署、Preview 环境、全球 CDN、免费 HTTPS | **Hobby 仅限非商业个人用途** | 见 §8.1， monetization 前必须确认套餐 |

> 一个必须现在就知道的事实（2026-11-10 核实 Vercel 官方 Fair Use / Hobby 文档）：**Hobby 只允许非商业个人使用**。投放广告、联盟链接为主、售卖商品/服务、收款、接收报酬来建站，都需要 Pro（$20/月）。但**「请求捐赠 / Sponsor」不算商业用途**。所以打赏可以留在 Hobby，广告与付费会员必须升级。

## 1. 技术选型

### 1.1 总体架构：把「后端」搬进构建期

「纯前端」和「每日定时采集」并不矛盾——**后端不是消失，而是被压缩成 GitHub Actions 里每天跑一次的构建期作业**，产出静态文件 commit 回仓库，Vercel 只负责分发。

```
[信源] 官方博客 / arXiv / HN / GitHub Trending+Releases / 中文媒体 / sources.yaml
   │
   ▼  GitHub Actions cron（每天 22:17 UTC = 北京 06:17）
[采集] 拉取 → 归一化 → 时间窗过滤 → 去重(simhash/embedding) → 打分
   │
   ▼  LLM 分层：便宜模型做分类/抽取，贵模型做主编（选 3-5 条 + 写「为什么值得关注」）
[编纂] 结构化输出(JSON Schema) → Zod 校验 → 链接可达性检查 → 禁用词检查
   │
   ├─► [内容]  content/days/2026-11-10.json + .md（结论先行、多色高亮、来源角标）
   ├─► [图文]  Satori(HTML→SVG) → resvg → sharp(WebP/AVIF) → public/cards/日期/
   ├─► [索引]  feed.xml / sitemap.xml / search index(Pagefind) / api/today.json / llms.txt / .md 镜像
   └─► [健康]  health.json（last_success、条数、耗时、降级标记）+ ping 死人开关
   │
   ▼  git commit（bot 身份）→ push main
[部署] Vercel 自动构建 → 全球 CDN → 纯静态 HTML（用户端无需任何请求）
   │
   ▼  用户浏览器
[本地层] 页面内存：信号标记 / 展开态 / 今日卡片（刷新即空）
          localStorage 仅存 signal:theme —— 零用户数据、零写请求
```

关键判断：**这个产品 95% 的可靠性问题发生在「采集期」和「构建期」，而不是「运行期」**。所以 SRE 的重心是 CI 质量闸门与死人开关，不是监控 API 和扩容。

### 1.2 选型表

| 层 | 选择 | 主要备选 | 为什么选它 / 何时该换 |
|---|---|---|---|
| 框架 | **Astro 5.x / 6.x**（锁 lockfile） | Next.js SSG、Vite+React、Nuxt | 内容驱动、默认零 JS、Content Layer + Zod 类型化内容、View Transitions 原生支持。日报是「复杂交互 < 20%」的典型，Astro 主场。**若将来做成富交互 SPA（大量跨岛状态）才换 Next/SvelteKit。** 注：Astro 6 移除了 `ViewTransitions` 组件，用 `ClientRouter`。 |
| 语言 | TypeScript `strict` | — | 内容 schema 与采集器共用类型，CI 就能挡住脏数据 |
| 样式 | Tailwind v4 + 单一 design token 源 | 原生 CSS | token 同时被站点与 Satori 图文模板消费，保证「网页与分享卡长得像一家人」 |
| 内容 | Astro Content Layer + Zod，JSON（结构化）+ MD（长文）双轨 | 直接 import JSON | 构建期强校验，坏内容直接让 build 失败，而不是上线后才发现 |
| 采集 | GitHub Actions + Node/TS | Python / Cloudflare Workers Cron / Vercel Cron | 与仓库同生命周期、密钥在 Actions Secrets、commit 回写天然；Vercel Cron 需函数（违背纯前端） |

| 搜索 | **Pagefind** | Algolia、Fuse.js | 构建期索引静态 HTML、查询全在浏览器、无服务无密钥、万页站点索引载荷可 <300KB。注意必须标 `data-pagefind-body`，否则索引为空；`prerender=false` 的页面不会被索引 |

| 中文字体 | 子集化（fonttools / cn-font-split）+ 系统栈兜底 | 直接引全量 Noto Sans SC | **中文站性能第一杀手**：全量字体 3–8MB。子集化后通常 <200KB，是「高级体验」的地基 |
| 分析 | Vercel Web Analytics / Speed Insights；`/status` 自暴露 | Google Analytics、Plausible | 无第三方脚本 → 隐私与性能双赢。Hobby 免费 5 万 events/月 |
| 监控 | healthchecks.io 免费层（死人开关）+ `/health.json` + Actions 日志 | UptimeRobot 页面探测 | cron 可能被延迟甚至丢弃，需要「没跑成功就告警」，而不只是「页面还活着」 |
| 质量 | Lighthouse CI（预算门槛）+ 链接检查 + Playwright 冒烟 | 人工看 | 把性能与可用性变成 CI 里会失败的断言 |
| 包管理 | pnpm + 提交 lockfile | npm | 构建可复现；配合 Dependabot |

### 1.3 明确不做（及理由）

- **不用 Vercel Functions / ISR / SSR**：日报一天只变一次，SSG 足够；引入运行时等于引入故障面，且破坏「纯前端」承诺。
- **不用 Headless CMS**：多一个供应商、密钥、限流与故障点。**Git 就是 CMS**，还白送版本史、PR 审阅、`git revert` 秒级回滚。
- **不用 Algolia / 任何搜索服务**：Pagefind 零基础设施。
- **不用 Web Push**：需要服务端与订阅管理；改用 **`.ics` 日历订阅 + PWA 安装**（见 §8.2），纯静态即可实现留存。
- **不用公开计数 / 评论 / 账号 / 持久化用户状态**（v0.2 追加）：无后端做不了，且恰好是产品差异点（§6）。访问量增长只影响 CDN 带宽，不影响并发与数据库。
- **不全文转载**：只做摘要 + 结论 + 原文链接（§8.1 合规）。

## 3. 产品原型与交互设计

> 可点击原型见 `prototype/index.html`（单文件、零依赖、可直接双击打开）。

### 3.1 信息架构（历史 v0.2；v0.3 刊期轴已移页脚，当前按产品基线评审）

```
SIGNAL
├── 刊期轴（常驻，非页面）  近 7 期日期 + 该期主线，点击直达 · ←/→ 翻期
├── 今日 /                 主编视角的一天（默认落地页）
├── 本周 /week             三主题归并 · 七期主线 · 主题演变图 · 项目短名单
├── 项目 /projects         「项目档案」，介绍优先，数字放最后
├── 往期 /archive          昨日摘要前置 · 日期 · 主题 · 搜索 · 时间胶囊
├── 状态 /status           采集/构建健康 + 架构说明（零运行期服务）
└── 生成今日卡片            弹层，一次性 Canvas 产物，不是页面、不是模块
```

**去掉了 `/me`**。纯静态刊物运行期没有服务、没有用户表，就不该有一个「我的」入口去暗示账户存在。

### 3.2 关键页面与交互（历史 v0.2 记录；默认字段与布局以项目规约 v0.3 为准）

**① 今日（核心页）——扫描优先**
- 报头：期号 + 超大衬线日期；刊期轴在其下常驻。
- 主线一句话（给结果，不给铺垫）+ 导语（说清今天这几条为什么放在一起）。
- **30 秒速览**：本期全部条目的结论编号列完，不点开就能读完，点击可跳到对应条目。
- **主题分布信息图**：先看重心，再看条目。图是信息压缩，不是气氛。
- 条目（结论前置，展开不是必需动作）：
  `编号 / 分类 / 标题` → `结论` → `为何关注` → `关键事实（3–4 个数字）` → `适用场景` → `来源 / 读全文 / 信号标记`。
  **展开只放**：事件全文、边界与存疑、完整来源列表。
- **只看结论模式**（`b`）：把条目压成「标题 + 一行结论」的索引视图，10 秒扫完一期。
- 底部：读完 → 生成今日卡片 / RSS / 日历（转化在价值交付之后，不是弹窗）。
- 左栏常驻「本期索引」，键盘 `j/k` 翻条目、`Enter` 展开。

**② 项目档案**：日 / 周切换 + 主题筛选。每张卡按**「定位 → 解决什么 → 场景 → 不适合 → 为什么现在 → 事实数字」**顺序排布，右栏才是增量、累计、首次上榜、连续在榜、走势与同类可选。回答的是「我今天该不该花十分钟了解它」，不是「谁排第一」。主题分布图放在列表之后。

**③ 本周**：三主题归并（不是按日期罗列）、七期主线时间线、主题演变面积图、项目短名单、「本周被忽略的一条」。目的是看出一周的走向。

**④ 往期**：昨日整期摘要前置，全部刊期列表，搜索，时间胶囊，开放层入口。

**⑤ 今日卡片**：一次点击 → Canvas 出图 → 下载。含日期、主线、全部结论、本次标记；**不保存、不上传、不跨天累积**，弹层里明写。

### 3.3 视觉与动效语言：纯文本排版（v0.3 覆盖本节）

- **白底 `#FFFFFF` / 墨 `#151514` / 两阶灰 `#4C4C46`、`#64645E` / 唯一强调色朱红 `#A8332A`**。深色模式为 `#141413` 底。无卡片、无边框块、无底色区、无阴影、无渐变、无 emoji 图标；全站只有两三条功能性的发丝线，条目之间**靠 52px 留白 + 序号分组**。
- 全站无衬线（PingFang SC / Noto Sans CJK SC），数字 `tabular-nums`。**放弃 v0.2 的米色纸 + 衬线报头**：那套「编辑部风」已成为生成站最泛滥的模板。
- **字号只留四档**：主线 54 / 条目标题 21 / 正文 16 / meta 13.5，跨度大才有主次。正文行高 1.8–1.9，meta 对比度 ≥ 4.5:1，禁止 10–11px 与「变浅 = 次要」。
- **高亮**：大标题只让一个关键词变朱红、不用底色（54px 中文的 em box 会让色块浮在字上，很脏）；正文用极淡双色底，不做四色下划线轮换。
- 「配图给够」由**承载数据的信息图**满足，且只在内页出现：主题分布条、7 日走势、主题演变面积图、30 期密度条。不用吉祥物插画、不用 stock photo、不写「用来判断…」这类图注。
- 动效只做翻期连续性与展开的渐次披露，`prefers-reduced-motion` 全关。
- **单栏 760px**，不再有左栏索引、双栏基线、刊期轴。信息不是删掉，是移到页脚或折叠区。

### 3.4 必须设计的边界状态

采集失败（保留上一期并显式标 `degraded`）、当日条数不足（不发空刊）、离线（PWA 可读已缓存期）、窄屏（单栏，刊期轴横向可滚）、**无 JS（正文与全部结论仍完整可读）**、动效关闭、键盘 only、页面刷新后信号清空（明示「仅本次浏览」，不假装持久化）。

## 4. 每日信息采集定时任务规则 ★

### 4.1 触发时间与可靠性（已按 GitHub 官方文档核实）

```yaml
on:
  schedule:
    - cron: '17 22 * * *'   # 22:17 UTC = 北京次日 06:17，主刊
    - cron: '43 4 * * *'    # 04:43 UTC = 北京 12:43，午间追更/勘误（append-only）
  workflow_dispatch:        # 手动重跑
  repository_dispatch:      # 外部兜底触发
concurrency:
  group: daily-signal
  cancel-in-progress: false
permissions:
  contents: write           # 最小权限，仅回写内容
jobs:
  collect:
    runs-on: ubuntu-latest
    timeout-minutes: 20
```

规则与依据：

| 规则 | 做法 | 原因 |
|---|---|---|
| **避开整点** | 用 `:17` / `:43`，不用 `:00`/`:30` | 官方明确指出整点高负载时 schedule 会延迟，负载过高时排队作业**可能被直接丢弃**；社区实测可延迟 15–45 分钟 |
| **时区** | 推荐写 UTC 并在代码里用 `Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Shanghai'})` 换算目标日 | 官方虽支持 `timezone: IANA`，但 UTC 更可复现、与 GitHub/arXiv 的 UTC 日界一致；若用 `Asia/Shanghai`（无 DST，安全）需留意文档关于 DST 跳时的说明 |
| **最短间隔** | ≥ 5 分钟 | 官方下限 |
| **默认分支** | workflow 必须合入 `main` | 只在默认分支注册 schedule；手动 dispatch 能在别分支跑，容易造成「手动能跑、定时不跑」的错觉 |
| **60 天自动禁用** | 每天自动 commit 天然保活；另加月度 issue 心跳 | 公开仓库 60 天无活动会自动停用定时工作流；本项目每天有 commit，恰好免疫 |
| **别只信 cron** | 死人开关 healthchecks.io：成功才 ping，超时未 ping 即告警 | schedule 是 best-effort，可能被丢弃；必须有「没跑成」的检测 |
| **三重触发** | cron（主）+ repository_dispatch（外部 cron 兜底，如 Cloudflare Workers Cron）+ workflow_dispatch（人工） | 单点不可靠 |
| **fork 默认禁用** | 文档化说明 | fork 仓库定时工作流默认关闭 |
| **幂等** | 采集结果算 fingerprint，与当日文件一致则不 commit | 避免重复部署、避免无意义 diff |
| **并发** | `cancel-in-progress: false` + group | 追更不与主刊互相取消 |

### 4.2 采集规则

- **时间窗**：滚动 24 小时（主刊）/ 6 小时（追更），以 Asia/Shanghai 自然日归档；跨时区信源统一转 UTC 排序。
- **信源白名单**（`config/sources.yaml`，可 PR 贡献）：官方博客/发布说明、arXiv、Hacker News、GitHub Trending 与 Releases、少量高质量中文媒体。**不使用来路不明的 AI 聚合日刊**（此前日报踩过：低质聚合源会混入未经验证的数据）。
- **筛选打分**：时效性 × 权威度 × 影响面 × 与本刊栏目相关度 − 重复度 → 取 **3–5 条 AI + 5–6 个项目档案**。宁缺毋滥。
- **去重**：URL 归一化 + 标题/摘要 simhash；与近 14 天历史比对，**与既往推送过的选题去重**（延续已有日报的「已推送选题」机制，写成 `content/history.json`）。项目档案另有「首次上榜 / 连续在榜」字段，避免把老项目当新闻推。
- **AI 条目必填**：一句话结论、为何关注、关键事实（3–4 个可核查数字）、适用场景、事件全文、边界与存疑、来源链接（可访问）、标签、高亮关键词。
- **项目档案必填**（v0.2 新增）：一句话定位、解决什么问题、适用场景（≥2）、什么时候别用、为什么今日/本周值得看、主题 topics、语言/许可、今日与本周增量、累计 star、首次上榜、连续在榜、7 日走势、同类可选。**介绍字段任一缺失即视为不合格内容**，不允许只输出名字 + 数字。
- **成本闸门**：每日 token 预算上限、批处理、结果缓存；超预算自动降级为「规则摘要 + 原文链接」。

### 4.3 质量闸门（不过则不让 commit）

1. Zod schema 全字段强校验（含日期、枚举标签、URL 格式）。
2. **来源链接 HTTP 可达性检查**（防幻觉引用，这是 AI 日报最容易翻车的地方）。
3. 条数下限（AI ≥ 3、项目档案 ≥ 3）；**项目档案 5 个介绍字段非空且不是 README 首句复读**（可用长度 + 与描述重合度断言粗筛）；不满足 → 标 `degraded: true` 并保留上一期，不静默发空刊。
3b. **字段分层断言（v0.3）**：默认展示 `verdict / why`；`facts / scenes / event / caveat / sources` 静态 DOM 常驻，通过原生展开可达。内容完整性不能用是否平铺判断。
4. 禁用词/绝对化表述检查（「彻底颠覆」「百分百」等）。
5. 历史不可变：**当天内容一旦发布不改写**，勘误只能 append 到 `amendments[]` 并保留时间戳。
6. 人工 override：`config/overrides/2026-11-10.yaml` 优先级最高，用于纠正模型判断。
7. 产物体积与图片尺寸预算检查；超出则 build 失败。
8. 生成 `health.json`（last_success、条数、耗时、降级、版本）并 ping 死人开关。

## 5. 生成图文的要求 ★

图文不是装饰，是**这个产品最主要的传播载体**：能被截图转发、能被搜索引擎与社交平台抓取、能被 AI 引用。

### 5.1 三层产物

| 层 | 用途 | 生成时机 | 尺寸 |
|---|---|---|---|
| 每日封面 | OG / 搜索 / 社交卡片 | 构建期（Satori） | 1200×630（另出 1:1 备用） |
| 单条卡片 | 小红书 / X / 微信单条转发 | 构建期 | 1080×1440、1200×675 |
| 整期长图 | 微信/朋友圈一期读完 | 构建期 | 1080 宽 × 自适应高，分段防超长 |
| 今日卡片 | 本期主线 + 全部结论 + 本次浏览标记 | **客户端 Canvas** | 1080×1440 起 |

分工理由：SEO/OG 必须构建期确定性产出；**今日卡片是一次性、无状态的产物**（不保存、不上传、不跨天累积），天然只能在浏览器画。v0.2 起不再有「个人兴趣指纹 / 个人年报」这类需要持久画像的卡。

### 5.2 链路与确定性

`Satori(HTML/CSS → SVG) → resvg → sharp(WebP/AVIF)`，全程在 Actions 内，产物提交到 `public/cards/<date>/`。
**确定性要求**：固定子集字体、固定排序、固定随机种子、无时间戳水印 → 保证相同输入产出字节一致，`git diff` 干净，不会每天制造无意义的大二进制 diff。

### 5.3 硬性规范（写进 CI 断言）

- 尺寸矩阵与安全区：四周 ≥ 72px（@1080）；二维码/短链固定在右下安全区内。
- **中文最小字号 28px @1080**（缩略图里仍能读），标题 56–72px，单卡正文 ≤ 6 行、≤ 120 字。
- 结论先行：卡片第一屏必须是「一句话结论」，不是标题堆砌。
- **关键词多色高亮**（每条 2–4 个，颜色轮换）、**配图给够**——「配图」一律指**承载数据的信息图**（主题分布、走势、演变、密度），不用吉祥物插画、不用 stock photo。不要纯黑文字墙，也不要用装饰冒充信息量；这条写进内容规约，由 CI 检查。**v0.3 补充**：本节规格针对 OG / 单卡 / 长图等**传播物料**；网页 UI 阅读界面按 §改版决议 v0.3 降级，避免首屏出现四色高亮与图表。
- 每卡必有：品牌标识、日期、来源角标、短链/二维码、期号。
- 不用 stock photo；不用未授权字体与图片；字体随产物子集化嵌入。
- 输出 WebP/AVIF，单图 ≤ 150KB（长图 ≤ 600KB）；同时保留 `alt` 文本与**纯文字 `.md`/`.txt` 等价版本**（无障碍 + 可被 AI 抓取）。
- 深浅两套主题各出一版，或至少保证浅底深字在两模式下都可读。

## 6. 「兴趣 / 点赞」怎样与众不同 ★★

### 6.1 先明确要反什么

反的是：**公开计数带来的从众压力**、**二元点赞的信息量贫乏**、**点赞即遗忘（没有任何沉淀）**、**engagement bait**、以及「为了做社交而被迫引入后端」。纯前端约束不是缺陷——把它变成产品主张。

### 6.2 v0.2 修订：把「画像」降级为「一次性动作」

v0.1 在这里犯了产品定位错误：为了让差异化成立，硬造了一个 `/me` 目的地（雷达、集章、本地重排、导出导入）。但一个**只有今日数据、无账号、无服务端**的开源刊物，凭什么有「我的」？用户一眼就会觉得名不副实。v0.2 的处理：

1. **不显示任何公开计数**——保留。没有「1.2k 赞」，无攀比、无刷量、天然免疫作弊。
2. **四类信号**——保留，但**语义降级**：`有启发 / 想试 / 存疑 / 收藏` 表达的是「这条对我意味着什么」，用来决定**今日卡片上带哪几条**，而不是用来攒画像。
3. **信号只活在当前页内存**：不写 localStorage、不跨天、不上传、刷新即空，UI 上直接标注「仅本次浏览」。这比「存了又怕丢」更诚实，也彻底避开隐私与同步问题。
4. **删除兴趣指纹 / 雷达 / 集章 / 我的日报重排 / 导出导入**（移入 P3 可选「本地档案」，默认关闭，需显式开启并告知清缓存即失）。
5. **差异化从「给用户一个画像」改为「不给用户建档」**：在一个到处都要你登录、要你留痕、用计数制造焦虑的产品环境里，「读完就走，什么都不留下」本身就是最锋利的主张，也最适合开源纯静态项目。
6. **时间胶囊 / 年度主题榜**：保留，但做成**内容资产**（这一周、这一年行业在聊什么），不做个人年报。

### 6.3 必须考虑的点（清单，v0.2）

| 点 | 处理 |
|---|---|
| 高并发会不会打爆前端 | **不会**：无运行期服务、无写接口。见「改版决议」。状态页对外讲清这一点，是技术信任也是引流素材 |
| 隐私合规 | 无 cookie、无第三方追踪、无账号、无持久用户数据 → 合规负担极低；可作为首页主张 |
| 标记会不会显得没用 | 明确它的唯一用途（决定卡片内容），并在卡片上体现；不做「攒够了解锁」这类虚假激励 |
| 刷新即空会不会困惑 | 标签直写「仅本次浏览」，弹层再写一遍「不保存、不上传」；不弹确认、不道歉 |
| 性能 | 信息图全部内联 SVG，不引图表库；首屏 JS 预算 < 15KB；无 JS 时结论仍完整可读 |
| 无障碍 | 信号按钮有文字标签与 `aria-pressed`；全键盘可达；`prefers-reduced-motion` 下无动效 |
| 反馈如何反哺内容生产 | 不做静默遥测。用 GitHub Issues / Discussions 公开勘误与选题，或「复制反馈码自愿提交」 |
| 别让交互抢走阅读 | 信号条在条目末尾，一次点击完成；**指标优先级：读完率 > 信号使用率**（v0.2 起不再用展开率） |
| 商业接口 | 「云同步 / 自定义信源 / 年报 PDF」是本地做不到的三件事，仍是 P3 最自然的付费点；一旦做，必须重估「无账号」地基 |

### 6.4 「高级感」与差异化的关系

差异化不靠多一个模块，靠**克制得让别人不敢抄**：不显示计数、不建档案、不弹订阅、不追热点词、不做信息流、每期固定 3–5 条、宁缺毋滥。**少一个功能比多一个功能更难，也因此更像一份有主张的刊物。**

## 7. 高级体验怎么来

一句话：**不是加特效，是「零等待 + 零噪音 + 有节奏 + 有记忆」**。以下每条都可验收：

1. 静态预渲染，**没有加载骨架屏**（静态站有骨架屏就是架构错了）；LCP < 1.2s、CLS ≈ 0、INP < 100ms。
2. **中文字体子集化**；`font-display: swap` + `size-adjust` 防 CLS；系统字体兜底先出文字。
3. **View Transitions**：日期翻页像翻报纸，缩略图平滑过渡成下一页头图，站点有「连续感」而非页面跳转感。
4. **渐进披露**：先给结果 → 再说清「是什么、能解决什么」→ 再展现效果 → 最后讲原理。开头短、有当下感、不铺垫。
5. **多色高亮 + 数据图（限传播物料）**：核心关键词标出、配图给够但只给信息图（分布 / 走势 / 演变 / 密度），不要纯黑文字墙，也不要吉祥物插画。写进内容规约，机器强制检查。**v0.3：网页 UI 首屏不用多色与图表**，理由见改版决议。
5b. **v0.2 补充**：结论前置、30 秒速览、只看结论模式、字号下限与对比度下限都属于「高级体验」的硬指标，见「改版决议」与 `01-项目规约.md` §7。
6. 中文排版：行高 1.7–1.8、合理的中西文间距、标点挤压、`text-wrap: balance` 标题、`tabular-nums` 数字。
7. 微交互有物理感且可关闭；默认不发声、不振动。
8. 阅读态可控：主题、字号、行宽、专注模式、进度、键盘流（`j/k` `/` `f`）。
9. 尊重系统：`prefers-reduced-motion`、`color-scheme`、高对比、全键盘可达、图片 alt、文字版等价内容。
10. **零第三方脚本** + PWA 离线可读 + 失败时诚实解释（「今日采集降级，展示上一期」），而不是空白页。

**反模式清单**：自动播放、订阅弹窗、无限滚动、骨架屏、粒子背景、字数堆砌、公开计数、追踪像素、为了「高级」牺牲首屏速度；v0.2 追加：渐变、玻璃拟态、大圆角、彩色标签云、emoji 图标、雷达图、假仪表盘、卡片瀑布淡入、10–11px 浅灰小字；**v0.3 追加：米色纸 + 衬线报头那套「反 AI 味模板」、界面里解释界面、首屏平铺全部字段、同屏 ≥7 个视觉组、四色高亮与图表进首屏、为了「信息完整」不敢留白**。

## 8. SRE 与引流 ★

### 8.1 SRE：把可靠性左移到 CI

| 风险 | 检测 | 兜底 |
|---|---|---|
| cron 未触发 / 被丢弃 | healthchecks.io 死人开关（超时未 ping 告警）+ `/health.json` | repository_dispatch 外部触发 + workflow_dispatch 人工重跑 |
| LLM 挂了 / 幻觉引用 | 结构化输出 + Zod + **来源链接可达性检查** | 降级为「规则摘要 + 原文链接」；标 `degraded` |
| 信源改版 / 反爬 | 采集器契约测试 + 条数下限断言 | 保留上一期内容，不静默发空刊 |
| 构建失败 | Actions 状态 + Lighthouse CI 门槛 | Vercel 自动保留上一成功部署；`git revert` 秒级回滚 |
| 内容出错 | 每日 commit diff 可审阅 | 历史不可变，勘误 append；override 文件人工纠正 |
| 图片体积膨胀 | CI 断言单图/总产物体积 | sharp 压缩；必要时 Git LFS |
| 密钥泄露 | 最小权限 `contents: write`、Secrets 隔离、Dependabot、严格 CSP | 不用 `pull_request_target` 执行外部代码 |
| 流量暴涨 | Vercel Analytics + 带宽告警 | 内容哈希长缓存 + CDN；Hobby 100GB/月、100 次部署/天，超量即评估 Pro |
| 60 天禁用 | 每日 commit 天然保活 | 月度心跳 issue |
| 供应商锁定 | 产物是纯静态 HTML/JSON | 可一键迁到 Cloudflare Pages / Netlify / GitHub Pages 作冷备 |

**性能预算（写进 CI，超标即失败）**：Lighthouse ≥ 95；首屏 HTML < 30KB；首屏 JS < 15KB；单图 < 150KB；LCP < 1.2s、CLS < 0.05、INP < 100ms；`content-visibility: auto` 处理长归档页。

**可观测**：Lighthouse CI、Vercel Speed Insights / Web Analytics（Hobby 5 万 events/月免费）、`/status` 静态状态页、Actions 日志与每日 diff 审计。

**成本与合规**：GitHub Actions 公开仓库免费；Vercel Hobby 免费但**仅限非商业个人用途**；主要可变成本是 LLM API（靠分层模型 + 缓存 + 日预算封顶控制）。**求捐赠/Sponsor 合规；一旦上广告、联盟或付费会员，先升级 Pro（$20/月）**。

### 8.2 引流：按「零成本 → 复利」排序

1. **内容即渠道**：结论前置 + 一键速览 + 今日卡片 + 传播物料里的多色高亮与数据信息图 → 天然适合被截图转发；每天固定时间、固定格式（3–5 条）、固定版式 → 形成习惯回路。**网页 UI 本身保持纯文本单焦点**，好看的图是拿去传播的，不是铺在首屏的。
2. **分享层**：一键今日卡片（带短链 + UTM）、本周主题图、年度主题回顾 → 每张图都是带品牌的分发单元，且都是**内容资产**而非个人画像。
3. **订阅层**：RSS/Atom、邮件（Actions 构建期调用 Buttondown/Resend，不算运行时后端）、PWA、以及最独特的 **`.ics` 日历订阅**——把「每天 7:00 读日报」变成日历里一个 recurring event，纯静态、无后端、留存感极强。
4. **SEO**：全静态可索引 HTML、sitemap、canonical、JSON-LD（`NewsArticle` / `SoftwareSourceCode` / `Dataset`）、每日期与每仓库独立 URL、中英双语镜像扩大覆盖。
5. **AEO / GEO（AI 时代的新入口，最契合本题材）**：提供 `llms.txt`、每期 `.md` 纯文本镜像、`/api/today.json` 静态 API → 让 ChatGPT / Perplexity / 其他 AI 日报**能引用你**。这是 2026 年最被低估的流量来源，而一个「AI 日报」不做这件事说不过去。
6. **开放层**：可嵌入 badge/widget（别人网站引用 → 反向链接）、可复用的 GitHub Action、开放 `sources.yaml` 接受 PR → 从读者变贡献者。
7. **社区层**：GitHub 仓库本身就是分发面（README 样例、Star、Trending）；Issues 做勘误与选题，Discussion 做选题投票。
8. **复利层**：归档即知识库；季度/年度报告可被媒体引用、产生高质量外链；「一年前的今天」让旧内容持续产生新分享。

## 9. 怎么转化用户 ★

### 9.1 先定义漏斗，否则「转化」是空话

`访客 → 读完(不点开就读完全部结论) → 次日回访(D1) → 订阅 → 分享(带 UTM) → 深度(翻往期 / 本周 / 项目档案) → 支持(打赏) 或 付费(P3) → 贡献(Star / PR / 补信源)`

| 阶段 | 钩子 | 指标 |
|---|---|---|
| 读完 | 30 秒速览、结论前置、只看结论、5 分钟读完 | **读完率**（v0.2 起为主要指标，不用展开率）、读完用时 |
| 回访 | 每天固定 07:00、刊期轴、固定篇幅 3–5 条 | D1 / D7 回访率、PWA 安装率 |
| 订阅 | 读完后顺势给 RSS / 邮件 / 日历三选一 | 订阅转化率（按 UTM 归因） |
| 分享 | 今日卡片、本周回顾、年度主题榜 | 分享率、带链接回流 UV |
| 深度 | 项目档案、本周主题、往期与时间胶囊 | 跨栏目访问率、往期点击率、项目页停留 |
| 支持/付费 | 打赏、云同步、自定义信源 | Sponsor 转化、付费转化 |
| 贡献 | 开放 sources.yaml、勘误 Issue、PR | 贡献者数、外部 PR 数 |

### 9.2 关键设计原则

**转化不靠弹窗，靠「已经交付价值之后的自然下一步」**：
- 读完 → 「顺手带走一张卡 / 明天 7:00 见」→ 订阅三选一（此刻用户刚获得价值，阻力最小）。
- 标记了几条信号 → 卡片上体现出来 → 分享（带 deep link，天然拉新）。**不做「攒够 N 条解锁」**。
- 翻到本周 / 往期 → 看到一周的走向 → 订阅。
- 项目档案帮人做完一次选型 → 该页被引用、被反链。

**留存靠节奏而非推送轰炸**：固定时间 + 固定篇幅 + 固定版式 + 可变内容，构成习惯回路；不要靠通知、集章或连续天数胁迫把人拉回来。

### 9.3 变现路径（与 Vercel 条款严格对齐）

- **Phase 1（Hobby 合规）**：GitHub Sponsors / 爱发电 / Buy Me a Coffee。**「请求捐赠」明确不属于商业用途**，可放心做。
- **Phase 2（需升级 Vercel Pro $20/月）**：广告、联盟链接、付费会员、企业版 API。
- **付费点必须卖「本地做不到的事」**：跨设备云同步、年度回顾 PDF、自定义信源、早鸟时段、API 配额。这也是全项目**唯一**需要考虑引入最小后端（如 Vercel Functions + KV）的地方——届时请重新评估「纯前端」这条约束是否仍要坚守。
- **反指标**：不以 PV 为北极星。看 D7 回访率、订阅转化、分享回流、每条展开率。一个日更产品的价值在「被当成习惯」，不在「被偶然刷到」。

## 附录：本次已核实的事实（2026-11-10）

- Vercel Fair Use / Hobby 文档：Hobby 限非商业个人用途；广告、收款、联盟、售卖需 Pro/EntERPrise；**请求捐赠不算商业用途**；Hobby 含 100GB 带宽、100 次部署/天、5 万 Web Analytics events/月。
