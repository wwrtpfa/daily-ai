## v0.6 玻璃磨砂（当前视觉依据，2026-11-10）

用户继续否定 v0.5，并明确要求“玻璃磨砂，高级优雅感”。当前候选视觉按这一要求实施，尚未由用户确认定稿。

- 取消深色固定侧栏，使用悬浮磨砂顶栏；银白底、低饱和环境光、半透明边缘与柔和投影形成材质层次。
- 主线、正文、项目、搜索、周观察、状态及分享弹层使用同套玻璃材质；阅读区透光更低，保持字形清晰。浅色与深色均覆盖。
- 圆角按组件为 9–27px，允许受控渐变、投影与 backdrop-filter。这是用户明确指定的方向，覆盖 v0.3/v0.5 的相反视觉限制；不增加动态粒子、持续动画或第三方脚本。
- 色彩及材质唯一来源为 `config/design-tokens.json` 的 `color / material / art`；CSS 提供不支持背景模糊时的实色回退。原创玻璃叠层图分别提供桌面和手机构图。
- 无运行时后端、无账号、无用户数据持久化与原生证据展开等约束继续有效。现有搜索、项目筛选、选条分享和下载继续保留。


## v0.5 UI 重构（2026-11-10，历史候选）

用户明确否定 v0.4 视觉，要求重新设计 UI。v0.4 的功能实现保留，视觉不作为设计依据。当前版本是新方案的可操作实现，未经用户视觉定稿。

- 桌面采用深墨蓝导航侧栏、冷白工作区、当期主线与独立阅读区；目录及项目入口位于右侧，避免正文反复承担导航职责。
- 钴蓝为强调色；字体不再锁定 54/21/16/13.5 四档，采用标题、正文、操作与辅助标识的响应式层级。正文条目结论与原因 16px。
- 允许低曲率内容分组（4–8px）、功能边线和侧栏。旧 §11.0 的固定 760px 单栏、全站无卡片、朱红、禁止首屏一切图形、最大/次大字号比等不再约束本次 UI；不引入阴影、渐变、胶囊标签堆叠或假数据仪表盘。
- 主线流程图是项目内原创 SVG（桌面及手机两种构图），只表达任务交付流程，不是统计图；源码由生成器与 design-tokens.json 共同生成，没有引用第三方模板、站点截图或外部 UI 组件库。
- 项目页改为项目身份与介绍网格；往期改为搜索与刊期网格；一周观察改为主题分组；分享弹层与深色主题采用同套视觉。
- 手机收起侧栏，使用横向导航和横向主线配图，390px 下首屏可见首条标题与正文开头。原生证据展开、搜索、日周筛选、分享复制与下载继续工作。

上述仅覆盖视觉冲突；纯静态、无账号、无写请求、用户状态不持久化与内容证据约束继续有效。


## v0.4 原型实施决策（2026-11-10）

用户明确要求助手自主完成原型与功能，本轮不再等待逐项选择。下列决策已落实为可操作原型，生产架构约束继续有效；不等于用户确认视觉定稿。与下方历史 v0.2/v0.3 功能描述冲突时，本节为当前原型依据。

- D01：默认直接阅读摘要；合并重复的速览、只看结论入口，证据使用原生 details。
- D02：四类临时信号改为“带走这条”，唯一用途是决定分享内容；不承诺收藏与找回。
- D03：未选条目打开分享时默认整期；已选则只分享所选。弹层可取消、全选、清空，零选中禁止复制和下载。换页与刷新清空选择。
- D04：今日末尾展示项目介绍入口，直接定位项目；演示样例不伪造新闻与项目的因果关联。
- D05：日周统计分别排序；近七期主题回到具体条目，短名单定位指定项目；所有统计注明演示。
- D06：桌面与手机首屏进入具体阅读，无侧栏、圆角卡片、四色标签或首屏图表。小屏标题缩放到 35px，属于四档桌面字号规则的响应式例外。
- D07：本轮交付五类页面、七个独立刊期、搜索/筛选/分享/下载资源。真实采集、生成图文、生产工程、自动化部署和线上性能验收仍属后续生产工作。

原型采用零依赖 Python 静态生成，HTML 阅读不依赖 JS；JS 仅增强主题、筛选、搜索和出图。生产 schema 与采集器尚未建立，`prototype/demo-data.json` 仅为样例源。样例来源只有发布方主页，已明确说明不是新闻原文证据。

当前仓库只有文档和 `prototype/index.html`，没有生产工程、工作流和可复跑的 39 项测试。原型使用演示数据，不能当作已核实新闻或线上运行证据。

- v0.3 是待评审候选，不能因交互冒烟通过就自动定稿。

- 现行视觉约束暂保留；后续调整须先给出可查看的原型并同步规约，不通过随意换皮改变约束。

## 2. 产品任务与范围

沿用蓝图中的 AI / GitHub 日报方向，不自行把产品改成工具目录或信息流。

| 任务 | 用户要获得的结果 | 验收方式 |
|---|---|---|
| 了解当天变化 | 知道今天有哪些具体事件，以及值得关注的原因 | 不操作阅读设置也能读完各条默认摘要 |
| 判断项目是否值得了解 | 看懂它是什么、解决什么、适合谁、有何限制 | 项目介绍完整，能继续访问实际仓库与来源 |
| 核查结论 | 找到对应证据、数字口径和边界 | 每条有实际可访问的来源，展开与外链可用 |
| 补读历史 | 找到某日或某主题，不靠记住期号 | 历史独立 URL、搜索与返回路径可用 |
| 理解一周变化 | 看到跨天归并的主题及其证据 | 每个主题能回到支撑它的日报条目 |
| 传播或持续阅读 | 带走准确内容或选择订阅 | 卡片内容与选择规则一致，订阅到达实际资源 |

“读完率”“回访率”是产品目标，不能借此引入被禁止的追踪脚本或用户画像。实际测量方案若需要新增数据采集，应另行决策。

## 3. 页面职责

以下是待细化的页面契约；不代表所有页面都进入首期，也不冻结当前导航排列。

| 页面 | 主要职责 | 必须定清的内容与动作 | 不能用什么替代验收 |
|---|---|---|---|
| 今日 / 每日期 | 阅读一期内容 | 主线与具体条目的关系；默认字段；展开、来源、上一期；稳定条目锚点 | 一句大标题、只有静态截图 |
| 项目 | 理解与筛选项目 | 日周口径、项目介绍、限制、事实、仓库外链；从周报精准进入对应项目 | star 数字、只弹 toast 的按钮 |
| 本周 | 归并跨天变化 | 主题依据、相关条目、七日覆盖、项目短名单的落点 | 重复七天标题、无数据依据的趋势曲线 |
| 往期 | 找回内容 | 日期/主题/正文搜索范围、排序、无结果、清空与返回 | 搜索后仍只展示固定昨日摘要 |
| 状态 | 说明内容是否新鲜、出刊是否正常 | 最近成功、降级原因、实际展示期；架构说明次级呈现 | 演示日志冒充线上健康数据 |

所有拟进入首期的页面都要有“入口 → 用户动作 → 结果 → 返回”的闭环。未进入首期的功能写入后续范围，不能用一个失效入口假装已完成。

## 4. 必须评审的功能决策

| 编号 | 决策 | 当前矛盾 | 定稿要求 |
|---|---|---|---|
| D01 | 默认阅读、速览、只看结论的关系 | 三种入口复用同一批摘要，职责重叠 | 明确每种模式服务的任务；决定保留、合并或延后，不能只因原型已有就保留 |
| D02 | 四类信号的用途与命名 | “收藏”容易被理解为可找回，但刷新即空 | 如保留，明确对最终产物的实际作用；不突破无持久化约束 |
| D03 | 卡片是整期还是选条 | 蓝图有“决定带哪几条”，当前出图始终包含全部条目 | 冻结选择、取消、无选择、跨期标记的规则；预览与下载内容一致 |
| D04 | 今日与项目的关系 | 两个内容入口之间缺少明确关联规则 | 决定是否交叉关联、关联到哪一条；不要求每条新闻强塞相关工具 |
| D05 | 本周与项目周期 | 周报短名单只进入项目总页，项目日周共用名单 | 定义周期数据、排序和精准链接；标清哪些变化来自真实统计 |
| D06 | 首屏优先展示什么 | 当前大主线、长导语、留白先于具体内容 | 用桌面和窄屏原型比较阅读起点与后续节奏；不是只检查字号比例 |
| D07 | 首期范围 | 原型演示了 P0/P1/P2 页面，不等于一期全做 | 给每项功能写明本期、延后或移除及理由；同步蓝图路线 |

这些是待评审问题，不是已经批准的删减清单。产品决策要记录原因、原型版本、确认日期和受影响的规约条款。

## 5. 原型交付标准

### 5.1 先完成任务与结构

每个页面写出服务对象、主要问题、内容顺序和主要下一步。低保真阶段先验证信息组织和流程，再定颜色、字号、留白。

### 5.2 视觉与交互一起交付

- 评审范围包含首屏、完整页面、展开态、筛选态、搜索态、分享弹层及页脚；不能只给一张 hero 图。
- 提供桌面、平板、手机布局；记录实际 CSS 视口，不能把设置值直接当测量值。
- 使用长度合理的演示内容，并覆盖长标题、多来源、少量条目与长项目名。
- 演示内容和演示状态要明确标示，不能拿原型中的成功时间证明生产链路可用。
- 视觉选择通过后，将色彩、文字、间距和组件状态归入 `config/design-tokens.json`；原型内硬编码不能成为生产实现捷径。
- 外链、跳转、展开、筛选和搜索完成真实动作；尚未实现的动作在评审清单中标记，不计为通过。

### 5.3 状态矩阵

| 状态 | 原型/生产验收要求 |
|---|---|
| 普通阅读、展开与收起 | 内容完整，位置变化可理解，焦点有合理落点 |
| 首期与最新期 | 上一期/下一期有清楚的边界行为 |
| 搜索无结果 | 显示无结果与清空入口，说明仍显示内容是否属于搜索结果 |
| 筛选无结果 | 有说明和恢复全部入口 |
| 无 JS | 生产页面正文、来源、翻期、原生展开可用 |
| 采集失败、LLM 失败、条数不足 | 不发空刊，保留上一成功期，明确展示日期与降级状态 |
| 深色、窄屏、键盘与减少动效 | 信息可读，操作可达，弹层可关闭，无横向溢出 |
| 分享内容过长、字体未就绪、出图失败 | 不静默截掉必要内容；可分段或调整画布，失败可恢复 |

## 6. 定稿门槛

1. D01–D07 对首期有明确结论，范围、内容契约和页面职责一致。
2. 当前原型已实际打开，按任务逐页操作，保存实际截图和发现。
3. 主要流程与边界状态完成评审，视觉问题和功能问题分别记录。
4. 用户确认选定的产品与视觉方案；助手不得自行宣布定稿。
5. 同步蓝图、规约、原型与 token 后，再进入相应生产实现。

功能回归、视觉检查、产品确认、生产集成是四种不同证据。任何一项通过都不能替代其余项。
