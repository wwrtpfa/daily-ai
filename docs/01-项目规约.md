## v0.7 决策式日报与项目档案（当前产品依据，2026-11-10）

- **今日页首屏结果优先**：首屏给出一句判断（今天几件要动手、几件可以跳过）、按当前任务的直达入口与分组条目；不再让大标题、插画与留白先于具体内容。已发布刊期的主线与导语收进「本期主线与口径」折叠块，不删除、不改写。
- **条目默认层扩展**：条目默认可见「等级（今天该做 / 记一笔 / 不用动）→ 谁该做什么 → 与你有关，如果 → 否则」；`verdict / why` 仍默认可见，事实、边界与来源仍在原生 `<details>`。分组与动作句是编辑判断，与来源事实分开呈现。
- **项目页改为档案式**：默认可见「解决什么 / 谁在用 / 什么时候别用·边界 / 怎么开始（官方命令）/ 采集快照」；后端清单、同类可选与来源收进展开区。命令逐条来自官方 README，未运行的实测必须在页面标明。

- 无账号、无用户持久化、无第三方脚本、无 JS 可读与静态 HTML 优先等约束继续有效；图表、分组、档案与折叠说明均为静态 DOM。

## 2. 内容 Schema（唯一真源：`src/content.config.ts`）

```ts
import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const Signal = z.enum(['insight', 'try', 'doubt', 'save']); // 有启发/想试/存疑/收藏

const Item = z.object({
  id: z.string().regex(/^\d{4}-\d{2}-\d{2}#[a-z0-9-]+$/),  // 日期#slug，稳定不变
  kind: z.enum(['ai', 'github']),
  section: z.enum(['ai-coding', 'embodied', 'models', 'tools', 'papers', 'oss', 'industry']),
  title: z.string().min(8).max(46),

  // —— v0.3：以下四项必填；verdict / why 默认展示，facts / scenes 静态 DOM 可展开 ——
  verdict: z.string().min(10).max(90),          // 一句话结论，可含 2–4 个 <mark> 高亮
  why: z.string().min(30).max(180),             // 为什么值得关注（一行内可读完）
  facts: z.array(z.string().min(2).max(28)).min(3).max(4),  // 可核查的关键数字
  scenes: z.array(z.string().min(4).max(34)).min(2).max(4), // 适用场景

  // —— 展开区：事件全文、边界与存疑、完整来源 ——
  event: z.string().min(40).max(500),
  caveat: z.string().min(20).max(220),          // v0.2：冷静义务显式化
  sources: z.array(z.object({
    title: z.string(), url: z.string().url(), publisher: z.string(),
    publishedAt: z.string().datetime().optional(),
  })).min(1),

  highlights: z.array(z.object({               // 多色「下划线式」高亮，不用于 UI 装饰
    term: z.string().max(18),
    color: z.enum(['ochre', 'pine', 'indigo', 'gold']),
  })).min(2).max(4),
  tags: z.array(z.string()).min(1).max(4),
  fingerprint: z.string(),
});

// —— v0.2：项目档案是一等内容，不是 Trending 列表的一行 ——
const RepoProfile = z.object({
  fullName: z.string().regex(/^[\w.-]+\/[\w.-]+$/),
  oneline: z.string().min(12).max(60),          // 一句话定位：它是什么
  problem: z.string().min(40).max(240),         // 解决什么问题（禁止复读 README 首句）
  scenes: z.array(z.string().min(6).max(46)).min(2).max(5),   // 适用场景
  notFor: z.string().min(20).max(200),          // 什么时候别用（边界，必填）
  whyToday: z.string().min(20).max(160),        // 为什么今天值得看
  whyWeek: z.string().min(20).max(160),         // 为什么本周值得看
  topics: z.array(z.string()).min(2).max(6),
  language: z.string(), license: z.string(),
  day: z.object({ delta: z.number().int(), total: z.number().int(),
                  first: z.string(), streak: z.number().int(),
                  sparkline: z.array(z.number()).length(7) }),
  week: z.object({ delta: z.number().int(), total: z.number().int(),
                   first: z.string(), streak: z.number().int(),
                   sparkline: z.array(z.number()).length(7) }),
  alternatives: z.string().min(8).max(120),    // 同类可选
  sources: z.array(z.object({ title: z.string(), url: z.string().url() })).min(1),
});

const Day = z.object({
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  issue: z.number().int().positive(),
  headline: z.string().min(10).max(60),
  lede: z.string().min(40).max(220),            // v0.2：说清今天这几条为什么放在一起
  short: z.string().min(6).max(24),             // v0.2：刊期轴上显示的一期标题
  themes: z.array(z.tuple([z.string(), z.number().int()])).min(3).max(6), // 主题分布信息图
  density: z.enum(['quiet', 'normal', 'busy']),
  items: z.array(Item).min(3).max(6),
  brief: z.array(z.string()).min(3),            // v0.2：30 秒速览，由 verdict 生成，CI 校验条数一致
  amendments: z.array(z.object({
    at: z.string().datetime(), text: z.string(), targetId: z.string().optional(),
  })).default([]),
  degraded: z.boolean().default(false),
  generatedAt: z.string().datetime(),
  pipelineVersion: z.string(),
});

const Week = z.object({
  week: z.string().regex(/^\d{4}-W\d{2}$/),
  range: z.string(), headline: z.string(), lede: z.string(),
  themes: z.array(z.object({ name: z.string(), count: z.string(),
    points: z.array(z.string()).min(2).max(5) })).min(3).max(4),
  timeline: z.array(z.object({ date: z.string(), short: z.string(), count: z.number() })).length(7),
  shortlist: z.array(z.string()).min(3).max(5),
  ignored: z.string().min(30).max(240),         // 「本周被忽略的一条」
});

export const collections = {
  days: defineCollection({ loader: glob({ base: './content/days', pattern: '**/*.json' }), schema: Day }),
  weeks: defineCollection({ loader: glob({ base: './content/weeks', pattern: '**/*.json' }), schema: Week }),
  projects: defineCollection({ loader: glob({ base: './content/projects', pattern: '**/*.json' }), schema: z.array(RepoProfile) }),
};
```

**规则**
- `id` 一经发布永不改写；同一天内 slug 唯一。
- **历史不可变**：已发布的 `days/<date>.json` 只允许通过 `amendments[]` 追加勘误；禁止修改 `title / verdict / event / why / sources`。
- 所有日期以 **Asia/Shanghai** 自然日归档；时间字段一律 ISO 8601 UTC 存储、展示层换算。
- `history.json` 记录近 180 天所有 `fingerprint`，新条目相似度超阈值即丢弃（延续既有日报的「已推送选题」去重机制）。

**v0.2 追加规则**

- **内容完整与呈现分层（v0.3 覆盖）**：`verdict / why / facts / scenes` 全为必填；`verdict / why` 默认展示，其余字段在静态 HTML 常驻且原生可展开。CI 按 §4.11 断言，不再要求四项平铺。
- **项目档案五个介绍字段**（`oneline / problem / scenes / notFor / whyToday`）任一为空、或与仓库 `description` 重合度 > 0.8，视为不合格内容 → 该期标 `degraded`，不允许用「名字 + star 增量」凑数。
- `brief[]` 必须与 `items[]` 一一对应且顺序一致（30 秒速览由结论生成，不能另写一套说辞）。
- `short` 用于刊期轴，≤ 24 字，超出 CSS 截断但内容本身不得截断。
- `themes` 是**真实计数**（按条目涉及议题统计，一条可归多类），不是随意填的装饰数字。
- `caveat`（边界与存疑）为必填：厂商自选数据、未经第三方复跑的数字、规划 ≠ 产出，都要在这里显式标注。

## 3. 采集定时任务（`.github/workflows/daily.yml`）

```yaml
name: daily-signal
on:
  schedule:
    - cron: '17 22 * * *'   # 22:17 UTC = 北京次日 06:17，主刊
    - cron: '43 4 * * *'    # 04:43 UTC = 北京 12:43，追更/勘误（append-only）
  workflow_dispatch:
    inputs:
      date: { description: 'YYYY-MM-DD，默认今天', required: false }
      mode: { description: 'full | amend | dry', required: false, default: 'full' }
  repository_dispatch:
    types: [daily-fallback]
concurrency:
  group: daily-signal
  cancel-in-progress: false
permissions:
  contents: write
jobs:
  build-daily:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'pnpm' }
      - run: pnpm install --frozen-lockfile
      - name: Collect & edit
        env:
          LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          DAILY_TOKEN_BUDGET: '2.00'      # 美元/天，硬上限
          TZ: Asia/Shanghai
        run: pnpm daily:run --mode ${{ github.event.inputs.mode || 'full' }}
      - name: Quality gate
        run: pnpm daily:validate          # 失败即 exit 1，不产生 commit
      - name: Render cards & indexes
        run: pnpm daily:render && pnpm daily:index
      - name: Idempotent commit
        run: |
          git config user.name  'signal-bot[bot]'
          git config user.email 'signal-bot@users.noreply.github.com'
          git add content public
          if git diff --cached --quiet; then echo 'no change, skip deploy'; exit 0; fi
          git commit -m "chore(daily): $(date +%F) [skip ci]"
          git push
      - name: Dead man's switch
        if: success()
        run: curl -fsS -m 10 --retry 3 "${{ secrets.HEALTHCHECKS_PING_URL }}" || true
```

**不可协商的规则**

| 规则 | 值 |
|---|---|
| 触发分钟 | 必须用 `:17` / `:43` 等非整点，避开整点高负载（可能被延迟或丢弃） |
| 时区 | cron 按 UTC 写；目标日用 `Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Shanghai'})` 计算 |
| workflow 位置 | 必须合入默认分支 `main`；fork 需手动启用 |
| 保活 | 每日自动 commit 天然避免「公开仓库 60 天无活动自动禁用定时工作流」 |
| 兜底 | 死人开关（healthchecks.io）+ repository_dispatch + workflow_dispatch，三者缺一不可 |
| 并发 | 同 group 不取消进行中的任务 |
| 幂等 | 产物 fingerprint 未变则不 commit，不触发无意义部署 |
| 权限 | 仅 `contents: write`；禁止 `pull_request_target` 执行外部代码 |
| 成本 | 每日 token 预算硬上限；分层模型（小模型抽取 / 旗舰主编）；超预算降级 |
| 降级 | 信源或 LLM 失败 → `degraded: true` + 保留上一期 + 显式标记，禁止发空刊、禁止静默 |

## 4. 质量闸门（`scripts/validate.ts`，任一失败即 exit 1）

1. Zod 全字段校验；`items` 数量与 AI/GitHub 配比。
2. **每个 `sources[].url` 发起 HEAD/GET 可达性检查**（防幻觉引用，AI 日报第一大翻车点）。
3. 与 `history.json` 近 180 天做 simhash 相似度去重，阈值 0.82。
4. `verdict` 不含绝对化用语：颠覆 / 彻底 / 百分百 / 史上最 / 唯一 / 必然。
5. `highlights` 2–4 个且颜色不重复相邻；**每期至少 1 张承载真实数据的信息图**（主题分布 / 走势 / 演变 / 密度），不接受纯装饰图。
6. 图片：尺寸矩阵、安全区、单文件体积；中文最小字号在渲染模板中硬编码 ≥ 28px @1080。
6b. **UI 排版断言**（v0.2）：正文 ≥ 16px、meta ≥ 12.5px、所有文本对比度 ≥ 4.5:1；禁止 10–11px 与 `opacity < 1` 的文字；见 §11。
7. 产物总量预算：单期新增 < 3MB；首屏 HTML < 30KB；首屏 JS < 15KB。
8. `config/overrides/<date>.yaml` 存在时，校验其与生成结果已合并。
9. Lighthouse CI 门槛：Performance ≥ 95、Accessibility ≥ 95、CLS < 0.05、LCP < 1.2s。
10. 生成 `health.json`（last_success / itemCount / durationMs / degraded / pipelineVersion）并 ping 死人开关。
11. **字段分层断言**（v0.7 覆盖 v0.3）：`verdict / why` 必须默认可见；存在决策层时，`level / action / relevantIf / skipIf` 也必须默认可见且来自 `content/decisions/<date>.json`，不得由生成器硬编码；`event / facts / scenes / caveat / sources` 必须**存在于静态 HTML 的 DOM**（不得由 JS 异步注入），可默认折叠但必须一键展开；项目档案同理，`oneline / problem / whoFor / notFor / caveat / howTo` 默认可见、其余字段 DOM 常驻可展开；`brief[]` 条数 = `items[]` 条数。**折叠容器在生产实现中必须用原生 `<details>/<summary>` 或 `:target`，保证禁用 JS 时仍能展开**（原型用 JS 内存态是演示简化，P0 落地时须替换）。用 Playwright 断言，不是靠人看。
12. **项目档案完整性断言**（v0.2）：5 个介绍字段非空、与 README 描述重合度 < 0.8、`notFor` 与 `alternatives` 必填；`day` 与 `week` 两套数据都存在。
13. **无持久化用户状态断言**（v0.2）：产物中不得出现 `/me` 路由、不得出现写 `localStorage` 的用户数据键（`signal:theme` 例外）、不得有指向本站的 `fetch/POST/XHR` 写请求。

## 5. 图文规格

| 产物 | 尺寸 | 用途 | 命名 |
|---|---|---|---|
| `cover.webp` | 1200×630 | OG / 搜索 / 社交 | `public/cards/<date>/cover.webp` |
| `cover-square.webp` | 1080×1080 | 备用方图 | 同上 |
| `item-<id-slug>.webp` | 1080×1440 + 1200×675 | 小红书 / X / 微信单条 | 同上 |
| `digest-<n>.webp` | 1080 × 自适应（分段） | 微信整期长图 | 同上 |
| `*.svg` | 同源 | 可编辑、可 diff、可 AI 读 | 同名保留 |

- **链路**：Satori(HTML/CSS → SVG) → resvg → sharp(WebP/AVIF)。字体子集随产物嵌入，不依赖系统字体。
- **确定性**：固定字体、固定排序、固定随机种子、无时间戳水印 → 相同输入字节一致，`git diff` 干净。
- **版式**：四周安全区 ≥ 72px @1080；标题 56–72px；正文 ≥ 28px、≤ 6 行、≤ 120 字；品牌标识 + 期号 + 日期 + 来源角标 + 短链二维码（右下安全区）缺一不可。
- **内容**：第一屏必须是 `verdict`（结论先行）。**v0.3 分区**：网页 UI 中大标题只染一个关键词、正文用极淡双色底、信息图只在内页；**OG / 单卡 / 长图等传播物料仍按长期偏好给 2–4 个多色高亮 + 配图给够**。不用吉祥物插画、不用 stock photo、不用未授权素材。
- **等价内容**：每张图必须有 `alt`，且 `content/days/<date>.md` 提供纯文字版本（无障碍 + AEO/GEO 抓取）。
- **深浅**：至少保证浅底深字在两种系统主题下都可读；理想是各出一版。
- **客户端卡（v0.2）**：只有一种 —— 「今日卡片」。内容固定为 日期 / 期号 / 主线 / 本期全部结论 / 本次浏览标记；Canvas 在浏览器绘制。卡面必须印「纯本地生成 · 不上传」。**不做「我的兴趣指纹」卡、不跨天累积、不写 localStorage、刷新即空**。

## 6. 文案规约（机器可检部分已进 §4）

- **结构**：先给结果 → 说清「它是什么、能解决什么」→ 展现效果 → 最后讲原理。开头要有当下感和势能，不要长铺垫、不要不介绍。
- `headline`（今日主线）一句话给判断，不写「今日 AI 圈发生了这些事」这类废话。
- `verdict` 一句话结论，10–60 字，能脱离上下文独立成立（会被印在分享卡上）。
- `why` 必须回答「值得关注的原因」，写结构性变化、不写「很厉害」；能对照历史脉络更好。
- 每条 ≥1 个一手/权威来源，标注发布方；**只做摘要 + 链接，不全文转载**。
- 高亮与配图是**硬性要求**，不是可选加分项，但**按载体分层（v0.3）**：传播物料保留多色高亮 + 信息图给够；网页 UI 里降级以守住首屏单一焦点。「配图」始终只指**承载数据的信息图**，吉祥物插画不算数。
- `why` 写「结构性变化 + 对我意味着什么」，一行内能读完；`scenes` 写具体场景（谁、在什么情况下会用），不写「适用于广大开发者」这类空话；`caveat` 必须给出一条真实的边界或存疑。
- 冷静义务：厂商自选案例、未经第三方复跑的数据、规划目标 ≠ 当前产出，必须显式标注。
- 禁止：绝对化用语、无来源数字、标题党、把规划当事实、把传闻当发布。

## 7. 代码规约

- TypeScript `strict`；`noUncheckedIndexedAccess: true`；ESLint + Prettier 提交前必须通过。
- 设计 token 只在 `config/design-tokens.json` 定义，站点 CSS 与 Satori 模板共同消费，**禁止在组件里硬编码颜色**。
- 组件命名 PascalCase；文件 kebab-case；栏目/标签枚举以 `config/taxonomy.yaml` 为准。
- 岛屿（交互组件）默认 `client:visible` 或 `client:idle`；**首屏零 JS** 是硬要求。
- 动效只用 CSS / Web Animations / View Transitions，不引动画库；必须包在 `@media (prefers-reduced-motion: no-preference)` 内。
- 无第三方脚本、无追踪像素、无 cookie；CSP 默认 `default-src 'self'`。
- **v0.2：不持久化任何用户数据**。信号标记、展开态、卡片内容一律存于页面内存（JS 变量），刷新即空；`localStorage` 唯一允许的键是 `signal:theme`。**禁止**导出/导入 JSON、兴趣指纹、集章、跨天重排（这些属于 P3 可选「本地档案」，默认关闭且需单独 PR）。
- 所有交互元素有 `aria-label` / `aria-pressed` 且键盘可达；对比度 ≥ WCAG AA。
- 依赖最小化，新增运行时依赖需 PR 说明理由与体积；lockfile 必须提交；Dependabot 开启。
- `prototype/` 不参与生产构建，仅作交互参考，允许单文件零依赖。

## 8. Git 与发布规约

- 分支：`main`（生产）+ 短生命 feature 分支；`main` 受保护，PR 必过 `ci.yml`。
- Commit：Conventional Commits。机器提交固定 `chore(daily): <YYYY-MM-DD> [skip ci]`；人工 `feat|fix|docs|chore|content(scope): 说明`。

### 11.2 排版（写进 CI 断言）

- **v0.3 四档字号**：主线 54px / 条目标题 21px / 正文 16px / meta 13.5px，全站无衬线；首屏最大与次大之比 ≥ 2.5。

### 11.3 信息层级（扫描优先）

> **v0.7 覆盖说明**：第 3、5 条已被开头 v0.7 节替代。第 3 条现在允许显式的「与你有关，如果 / 否则」标签，因为它承载的是可跳过的判断，不再是纯段落关系；第 5 条的项目档案默认层扩展为「解决什么 / 谁在用 / 边界 / 怎么开始 / 快照数据」。其余条款继续有效。

1. **v0.3 单栏 760px**：一行文字导航 → 日期/期号 → 今日主线（唯一主角）→ 导语 → 一行「上一期」入口 → 三个文字工具 → 条目流。**刊期轴、期号元信息、阅读设置、关于一律移到页脚**；左栏删除。
2. 今日页首屏**只**包含：主线、导语、条数与上一期入口。**30 秒速览改为可折叠**（DOM 常驻）、主题分布图移到条目之后；`b` 只看结论模式保留。
3. 每个条目**默认状态**可见：编号 / 标题 / 结论 / 为何关注（**不带字段标签，靠段落关系表达**）。展开后：事件 / 关键事实 / 适用场景 / 边界与存疑 / 完整来源 / 四类信号。分类与来源数合并成一行 meta。
4. **「只看结论」模式**（`b`）：把条目压成标题 + 一行结论；`j/k` 翻条目、`Enter` 展开、`1–5` 切页、`←/→` 翻期、`/` 搜索、`g` 速览、`c` 出卡。
5. 项目档案**默认**可见：项目名 / 一句话定位 / 解决什么问题 / 语言许可与增量；**展开**：适用场景 → 什么时候别用 → 为什么现在 → 完整事实与走势 → 主题 → 同类。数字永远在介绍之后。
6. **解释型文案**（排序口径、并发说明、流水线日志、被忽略的一条）一律收进 `<details>`，不占用首眼。

### 11.4 无状态与运行期边界

- 不建 `/me` 路由；不出现「我的」「档案」「连续天数」等暗示账户的文案。
- 用户交互状态全部在内存；**刷新即空**，且 UI 明写「仅本次浏览」。
- 全站不得有向本站发起的写请求；所有图形（含今日卡片）在本地 SVG / Canvas 生成。
- 无 JS 时正文与全部结论仍完整可读：**生产实现必须用原生 `<details>/<summary>` 承载折叠区**，否则折叠内容在无 JS 时不可达；原型用 JS 内存态仅为演示简化，P0 落地时须替换。

### 11.5 边界状态

`prefers-reduced-motion`（无动效）、键盘 only、窄屏（单栏、刊期轴可横向滚）、无 JS、离线（PWA 已缓存期）、采集降级（保留上一期 + 显式 `degraded`）、当日条数不足（不发空刊）。
