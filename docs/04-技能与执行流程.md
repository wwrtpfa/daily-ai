> 2026-11-10｜给本项目的助手使用。技能是按任务加载的方法，不是网站依赖，也不是把全部技能内容复制进仓库。

## 1. 读取顺序

1. `AGENTS.md` 与当前用户要求。
2. `docs/01-项目规约.md`：项目架构、内容与工程硬约束。
3. `docs/00-项目蓝图.md`：方向、路线与历史方案，注意其中的候选/历史状态。
4. `docs/02-产品与原型基线.md` 与 `docs/03-开发规范.md`：产品决策、原型门槛、实施和验收。
5. 当前任务需要的技能 `SKILL.md`，只加载相关步骤。

用户明确修正产品前提时，更新决策状态，不能继续引用旧助手总结当作用户认可。遇到规约冲突列出准确条款，先同步文档，再按新决策实施。

## 2. 本项目的技能选择

| 任务 | 技能 | 使用条件与交付 |
|---|---|---|
| 产品任务、页面职责与需求澄清 | `product-design:get-context` | 先读项目与原型；把已知范围整理出来，只问真正缺失的问题 |
| 现有原型评审 | `product-design:audit` | 实际打开并逐步操作，保存与查看截图，列出视觉、流程、可访问性发现；源码检查单独标注 |
| 新视觉方向 | `product-design:ideate` | 产品任务明确后提供可比较的视觉方案；不得自行把候选宣布定稿 |
| 依据选定方案实现 | `product-design:image-to-code` | 忠实实现已选视觉、内容与交互，完成同视口对照 |
| 独立采用 Build Web Apps 进行新前端设计实现 | `build-web-apps:frontend-app-builder` | 作为另一条完整设计实现路线；遵守现有 Astro/纯静态约束，不与 Product Design 双重主导设计 |
| 页面调试与回归 | `build-web-apps:frontend-testing-debugging` | 按具体任务检查渲染、控制台、交互、响应式与证据，不以 build 代替可见验证 |
| 浏览器操作 | 已提供的 Browser/CUA 工具；需要 CLI 时用 `agent-browser` | 遵守工具自身规则，使用任务会话，完成时清理；不能因为一个接口失败就绕过安全限制 |
| 需要生成视觉素材或概念图 | `imagegen` | 由选定的设计技能触发；文字和实际控件仍由代码实现，数据图基于真实数据 |
| 架构图、流水线与状态图 | `archify` | 仅在这些图帮助技术评审时用，不给页面凭空增加装饰 |
| 形成可复用的专门技能 | `skill-creator` | 工作流反复使用、输入输出已稳定时再提炼；不在产品尚未明确时堆本地技能 |

使用前在当前环境技能目录定位并读取实际 `SKILL.md`。技能名称按能力匹配，机器上的绝对安装路径不写进工程配置。技能缺失要说明并采用可验证替代，不宣称已经执行。

当前没有 React/Next.js、账号、数据库、支付、视频、公众号发布需求，因此不默认加载对应技能，也不安装其依赖。未来确有需求时先核对架构边界。

## 3. 阶段交付

| 阶段 | 输入 | 必须留下的结果 |
|---|---|---|
| 认识项目 | 现有文件、用户反馈、可点击原型 | 实际存在/规划/演示/已验证的状态区分，当前问题与证据 |
| 产品整理 | 页面、用户任务、功能清单 | 功能范围、入口与结果、信息层级、状态矩阵、待决策项 |
| 原型定稿 | 产品任务、既有约束、候选视觉 | 完整页面、核心流程、桌面与窄屏、截图、用户选定记录 |
| 工程准备 | 批准的范围和原型 | schema、token、模块边界、版本锁定、执行命令 |
| 迭代开发 | 一项明确需求 | 实现、相应测试、浏览器证据与同步文档 |
| 集成验收 | 构建产物、真实信源与授权环境 | 成功链路和失败/降级证据、性能、状态与回滚 |

原则：先看实际原型，再提出产品判断；先定产品与原型，再落地对应页面。用户未批准的候选不能被包装为 CI 必须守住的“审美事实”。现行约束的调整也必须显式同步，不能由某个技能默认值悄悄覆盖。

## 4. 本地原型与清理

原型入口已经在仓库：`prototype/index.html`。它是零依赖 HTML，不需要先创建生产工程。

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory prototype
```

通过本机 HTTP 预览检查，不把本地文件上传第三方服务。保留服务会话标识，完成后正常中断，核查本任务进程退出。端口冲突时找出占用或换用空闲端口，不杀已有服务。

- `file://` 不可访问时，不能声称原型不存在，也不能把源码审查说成视觉检查；先按工具政策确认允许的预览路径。
- 原型在仓库中时，助手负责定位与启动，不把查文件工作转给用户。
- Browser/CUA 标签执行文档中的关闭/交付步骤；使用 `agent-browser` 必须执行 `agent-browser close`，错误退出也一样。
- 用户未要求保持预览时，最终停止临时服务并释放本任务会话；需要再次查看时可按上述命令重新启动。
